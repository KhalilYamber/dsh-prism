**简体中文** | [English](./README.en.md)

DSH 界面三档模式插件：原生 / 整洁 / 白话一键切换。整洁档保留产品原版的工具行语言，白话档把术语换成大白话，两者都把工具调用收成折叠组。新手看白话，老手要完整，同一套界面三种读法，降低 DeepSeek Harness 的上手门槛。

项目仍在持续迭代：跟进 DSH 接口演进、扩充工具与官方块覆盖、打磨折叠体验与长会话稳定性，欢迎试用与反馈。

## 为什么做这个

DeepSeek Harness 发布后，社区对它的批评集中在一点：**门槛**。

- 界面新闻：「一切皆插件」的设计十分依赖配置（YAML + 插件 + 效果组件 + 服务），「对高级用户而言功能强大，但对于只想快速用上可用智能代理的人来说，上手门槛较高」
- 极客公园：DSH「对非编程用户不是很友好」，像框架、不像成品，是给开发者的尝鲜版
- 社区开发者：「这玩意鬼才用，我为什么没事要插拔」

DSH 的毛坯房是刻意为之，但「想省事的人」和「要全功能的人」不该被迫接受同一套界面。dsh-prism 用三档模式回应这个矛盾：

| 档位 | 适用的人 | 界面表现 |
|---|---|---|
| **白话** | 想先用起来、不想研究术语的人 | 工具调用归组折叠：正式回复前的一串调用收成一行统计，点开展开后每行走白话文案（「正在读取一个文件的内容」），全篇 emoji 图标 |
| **整洁** | 想整洁、但不想改变原有信息读法的人 | 同样归组折叠，展开后每一行按**产品原版样式**呈现：单色线性图标 + 类别标题（`Bash` / `读取` / `编辑` / `工具调用`）+「·」+ 参数摘要，例如 `Bash · Run syntax check`、`工具调用 · get_goal · {}`；用宿主内置的官方 `ui-primitives` 组件渲染 |
| **原生** | 老手、需要完整信息的人 | 插件零接管，产品原貌原样渲染，一个像素都不改 |

默认原生档，切换一次即生效，且档位会记住（刷新页面或重启 DSH 后仍是那一档）。不想用的时候，卸掉插件，界面回到出厂状态，没有任何残留。

## 功能

- **侧栏入口**：侧栏底部「设置」上方一枚圆形按钮（官方 `sidebar.footer.action` 槽，与 WSL / 记忆等入口同排），显示当前档位首字（原 / 整 / 白），点开菜单切换「原生 / 整洁 / 白话」；菜单内含「隐藏复杂工具」开关（仅白话档生效）；**档位会记住**，刷新页面或重启 DSH 后仍是上一次选的那一档
- **整洁档 = 归组折叠 × 原版行**：
  - 与白话档共用归组与折叠统计行，差别只在展开后的每一行：用宿主内置的官方 `@deepseek-ai/dsh-client-ui-primitives` 原语（`DisclosureRow` / `StateDot` / 官方图标）渲染，标题与摘要按产品 `toolRowModel` 的同一套规则推导，视觉与产品原生工具行一致
  - 行结构：状态标识（取官方 `StateDot`）+ 单色线性图标 + 类别标题 +「·」+ 参数摘要；通用工具按产品的写法带上工具名（如 `工具调用 · get_goal · {}`）
  - 状态分两级：工具真出事（`isError`）显红；命令返回非零退出码（`grep` 没匹配、`head` 截断管道这类常态）显琥珀，文案「命令返回非零」
  - 展开后的内容按工具类型走官方语义块：命令族用官方 `TerminalBlock`（命令头 + 输出 + 复制按钮）、读取族用官方 `ReadBlock`（带行号）；其余工具走交付文档（`MarkdownText`）。官方原语取不到时退回原位，一块不丢
  - 折叠开关取官方 `FoldToggle`；宿主这版尚未提供它，自动走自绘兜底（「展开 ▾ / 收起 ▾」），宿主升级后自动生效
  - 不折叠复杂工具（信息完整度贴近原生）；脱敏与详情渲染沿用同一套底线
- **白话档 = 工具调用折叠组 × 大白话交付文档**：
  - 分段折叠行：**每两段正文之间的工具调用各收成一条**，收起时只显示一行统计「N 个工具 · M 次思考」（M 为该段内模型思考次数，按 assistant 输出的 reasoning 块计数；无思考时只显示工具数），行尾带该段状态（✓ 完成 / ● 运行中 / ✕ 有出错 / ⚠ 混合计数）
  - 运行中会说话：收拢行报「**正在忙第 N 件 · 该工具的白话文案 · 耗时**」；结算后回到统计口径（`N 个工具 · M 次思考`）
  - 展开面板按 **step 分段**：**运行中自动开面板，并只展开「当前进行中那一段」的思考原文**；轮次结算后自动收回成一条行（您手动点过的那一次说了算）。段头说实话：这一步有思考写「**思考完成**」，只调了工具写「**步骤完成**」；段头只管该段思考原文（默认收起，点开才铺）
  - **工具行与段头同一层常驻**（工作日志）：该段的工具行 / 重试行与段头左对齐、不随思考开合，归属由整段左侧的细线表达。工具行是手风琴，点开看**原生内容**：完整参数（命令不截断）+ 完整结果，均先脱敏
  - 答案步由插件自己渲染完整（产品的同 key 渲染器被压住，**返回 null 就是空白**，不存在「交还产品」这条路）：一行「思考」（默认收起，点开才铺原文）+ 紧随的正文，答案与它的来由连着
  - 让位的座位不占地方：折进面板的座位按 `display` 收起（只收工具 / 重试座位，或「已结算且渲染为空」的助手座位），切档或卸载时按轮次原样撤回 —— 用 `display` 而非 `hidden`，是因为产品在它那侧会无条件抹掉同名的 `hidden`
  - 隐藏复杂工具：21 个高级工具（目标 / 计划、子代理编排、后台任务、插件系统）在面板内默认折叠成白话摘要行，点「展开」即展开并打开详情；菜单开关可随时关闭折叠
  - 归组规则：以**有正文的助手步**为界把一轮切成若干段（正文之间各一段），每段一条折叠行、紧跟在这段正文之后；段内再按 step 分段。带思考但不带正文的步不构成边界（思考原文留在段里），答案步永远是边界、它之后的内容不进折叠；运行中随新调用累计，刷新重放后按同一规则归组，每个工具恰好显示一次
- **点开时钉住被点那一块**：开合会改变内容高度，而宿主的滚动所有者（`ui-chat` 的 `ChatView.tsx`：`ResizeObserver` 盯着流列，读者贴底时把视口拽到新底部）会让被点的那一行从指下溜走。插件在点击那一刻记下被点那一块的屏幕位置，随后把它钉住：被点的行不动，内容从它下面往下长。补位只写滚动位置，静默 320ms（最长 1.2s）自己撤，滚轮 / 触摸 / 滚动键一动立刻让开；中段阅读本来就不动，补位在这里不添乱
- **双语界面**：插件全部文案跟随 DSH 界面语言（简体中文 / English），设置里切换语言即时生效，无需刷新；工具白话文案、参数摘要、菜单与状态均有中英双语
- **数据脱敏**（两个折叠档共用同一底线）：
  - `token / secret / password / api_key / authorization` 等敏感参数名永不取值，整洁档的摘要同样过滤；参数里只有敏感键时摘要留空，不回退原始 JSON
  - 结果文本与摘要中的常见密钥形态（`sk-xxx`、`Bearer xxx`、`?token=xxx`、`key=xxx`）替换为占位符
  - 白话档额外把路径缩成文件名（`file_path` 等参数用 basename 呈现）；整洁档按产品原版规则显示路径，以贴近原版
  - 详情面板只展示脱敏结果，不暴露原始参数
- **原生档 = 产品原貌**：原生档下插件不注册任何工具行渲染器，交还产品原样渲染（含通用卡片）；整洁档与白话档才注册折叠组节点（以更低的 priority 同时接管 `tool-call` / `assistant-step` / `model-retry` 三个节点渲染器），切档时动态注册 / 注销、即时生效
- **可诊断性**：档位菜单一行体检（版本 + 三格注册状态 + 行距三本账）；控制台 `__PRISM_DIAG__` 存最近 6 次切段与最近 5 轮现场；可疑形态自动留痕（`__PRISM_DIAG_LOG__()` 读取、`__PRISM_DIAG_LOG_CLEAR__()` 清空），长会话里时好时坏的毛病也留得下现场
- **文案规则**：33 个工具规则表给出白话文案（如 `pwsh` → 「正在电脑上执行一条命令」），未进表的工具按参数名自动生成摘要。白话档下折叠组内每一行都按这套规则渲染；整洁档改用产品原版的类别标题与摘要规则（`Bash · …`、`工具调用 · 工具名 · …`），只在脱敏底线上保留插件自己的过滤

## 设计原则

- **纯展示层**：只改界面呈现，模型输入输出零改动，不影响 agent 的任何工作
- **原生零接管**：原生档不注册任何卡片，产品原貌完整回归；白话档把工具调用收成折叠组，组内工具行统一按白话规则渲染，官方工具卡片本身不被改动，原生档下保持原版
- **档位记忆**：选择的档位存浏览器本地（`dsh.prism.mode`），刷新页面或重启 DSH 后保持；其余界面状态（折叠组开合、菜单、隐藏复杂工具开关）仍是内存态，不留痕迹
- **跟随主题**：全部使用官方 `--dsw-alias-*` 设计变量，明暗主题自适应
- **失败大声**：注册与渲染的异常一律 `console.error('[prism] …')` 并记入体检面（`window.__PRISM_DIAG__`），绝不静默吞错
- **内容不吞不编**：数据拿不到就退回朴素呈现，不靠猜、不靠解析文本硬造；折叠不让内容丢失

## 安装

需要先装好 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（Node.js 22.19+ 或 24+）。

当前通过 GitHub 发布，克隆本仓库后以本地路径安装：

```sh
npx -y @deepseek-ai/dsh plugin --profile web add <本仓库目录>
```

也可以从 [Releases](https://github.com/KhalilYamber/dsh-prism/releases) 下载已发布的打包产物。启动 Web UI 后，侧栏底部「设置」上方会出现档位入口。

## 使用

1. 启动后点击侧栏底部「设置」上方的档位入口（显示当前模式）
2. 选择「白话」：一次任务里的工具调用归成折叠组，收起是一行统计，点开展开面板看每个工具的白话行与交付文档详情
3. 菜单里可开关「隐藏复杂工具」（仅白话档生效）
4. 选择「原生」：恢复完整原生界面
5. 档位会记住：刷新页面或重启 DSH 后仍是当前档；想回原生档，在菜单里切回「原生」即可

## 常见问题

**档位会记住吗？想清干净怎么办？**
会。档位存在浏览器本地（键名 `dsh.prism.mode`），刷新页面、关掉 DSH 再开都保持。想回到「原生档 + 无痕迹」，把档位切回原生即可；要连记忆一起清掉，在浏览器控制台执行 `localStorage.removeItem('dsh.prism.mode')` 再刷新。换浏览器或清掉浏览器数据之后，同样回到默认的原生档。

**为什么有些工具卡片看起来没变？**
`read`、`write`、`web_search` 等工具官方已有产品级原生卡片，插件不为它们注册替代卡片（原生档完全原版）；白话档把它们与其他工具一起收进折叠组，以统一的白话行展示，不改变官方卡片本身。

**为什么折叠行的状态点有红有琥珀？**
红＝工具真的出错了；琥珀＝命令返回了非零退出码（`grep` 没匹配、`head` 截断管道这类常态也算），文案写「命令返回非零」。这样助手连续跑管道命令时，不会一屏全是红点。

**白话档会影响 agent 干活吗？**
不会。插件只改界面显示，模型收到的输入输出与原生完全一致。

**点开详情后表格 / 代码块是什么效果？**
结果文本先脱敏，再交给官方的 `MarkdownText` 渲染（表格、代码块、标题、列表、行内代码与链接都在内）；取不到官方原语时退回等宽纯文本，绝不抛异常。

### v1.14.0（2026-09-24）
- **折叠卡片换上官方语汇**（主人 2026-09-24 点名：「折叠卡片的前端是否太不够自然了，能用上官方 ui-primitives 优化吗」）。查下来，整洁档的「行」本来就是官方 `DisclosureRow`，但**行尾的状态点、折叠开关、以及展开后装的内容**这三处还是自绘的。这一版换掉它们：
  - 状态点 → 官方 `StateDot`（运行中是追逐动画，与 `TerminalBlock` 头部那颗同源，行与卡片不会各说各话）
  - 折叠开关 → 官方 `FoldToggle`（`button` + `aria-expanded`，文案从自造的「展开」换成产品的「还有 N 行」）
  - 工具详情 → 命令族走官方 `TerminalBlock`（命令 + 输出 + 退出码 + 一键复制 + 自带高度折叠），读取族走官方 `ReadBlock`（带行号的文件块）
- **拿不到就退回原位**：官方原语取不到、或该工具不属于已接的族，一律退回原来的交付文档（`MarkdownText`）—— 内容一块不丢；未接的族**不许**冒充官方块
- **不重复、也不丢**：官方块自己带命令头 / 文件名，外层参数区就摘掉 `command` / `file_path`（真机上原本命令会显示两遍）；其余参数（`cwd` / `timeout` / `offset`…）照旧留着
- **状态分两级**（主人 2026-09-24 看到成排红点后点名）：过去「工具失败」与「命令返回非零」都算 `err`，于是助手连跑 `grep` / `head` 管道（退出码非零）时一屏折叠行全是红点。现在 `isError`（工具真出事）才红；只是退出码非零的走琥珀（复用既有的 `mixed` 档，文案「命令返回非零」）
- **为什么只接两类**：搜索 / 网页 / 差异那三个官方块要的是产品 tool 插件自己塞进结果里的结构化元数据（`path` / `offset` / `lines` / `totalLines` 这类字段），插件这一层拿不到；靠解析文本反推会造出「看着对、其实错」的内容（红线：一块都不许吞，也不许编）
- **验收**：回归桩新增 3 条断言（命令族二选一 / 读取族二选一 / 未接族不冒充官方块），**正向 154/154 全绿**；差分对照跑 v1.13.0，结果区断言变红。另修一处装置缺口：`PRISM_REAL_PRIMITIVES=1` 在 WSL 里跑 Windows 版 node.exe 时传不过去，新增 `--real-primitives` 命令行开关

## 架构（全部实现位于 `lib/client.js`）

```
TOOL_RULES        规则表：33 个工具 → 白话文案与参数摘要声明
ARG_NAME_RULES    参数名规则：无显式声明的工具按参数名自动生成摘要
SENSITIVE_KEY     敏感参数名（任何情况下不展示其值）
```

注册是动态的：`conversation.chat.node` 的 `tool-call` 渲染器仅在白话 / 整洁两档注册（以 `priority: -1` shadow 产品 ToolCallTree；keyed 槽同 key 同 priority 的注册会抛错，更低 priority 者胜出），原生档零注册，产品界面原样呈现。折叠组面板内的工具行由插件直接渲染（白话卡片 / 原版行，展开后的详情走官方语义块或交付文档），不经 `tool.call.toolview` 槽分发（该槽的消费方是产品 ToolCallTree，折叠档下已被 shadow）。

分区与分段：`computeGroups()` 先按「有正文的助手步」把本 turn 的节点切成若干段（正文之间各一段；答案步是边界，它之后不折；只有工具头的步不构成边界），每段再交给 `computeSegments()` 按 `step` 切列（段边界取同一 step 的最后一个工具或重试节点，每个节点恰好渲染一次）。段头用官方「思考完成」的说法，段内条目复用 `ToolCard` / `NativeToolRow` / `RetryRow` 三种行。每条折叠行的渲染权按「会话 + turn + 段标识」认领（`useGroupClaim`），开合状态同键记账。耗时取工具块上的 `callTime` 与 `time` 之差，运行中的行由 `useTick()` 的秒级节拍推进（仅在存在运行中行时启动）。

| --- | --- |
| `tools` | 工具名（数组）；多个工具共用一条规则 |
| `doing` / `done` | 进行中 / 完成的白话文案；缺省时自动生成通用文案 |
| `complex` | 标记复杂工具：白话档默认折叠成一行，点击可展开 |
| `noArgs` | 不显示参数摘要（保持原有行为） |
| `arg.pick` | 候选参数键，按序取第一个非空字符串 |
| `arg.mode` | 呈现方式：`file`=路径只留文件名 / `raw`=原文 / `short`=截断（配 `max`）/ `count`=数组计数（配 `unit`）/ `wrap`=（值）包裹 / `fixed`=固定文案 |
| `arg.prefix` | 摘要前缀 |
| `arg.fallback` | 参数缺省时的文案；不填则不显示摘要 |

### 新增一个工具

1. 在 `TOOL_RULES` 加一行，**只写工具名即可**：doing/done 自动生成通用白话文案，参数摘要由 `ARG_NAME_RULES` 按参数名自动生成（如 `file_path` → 「文件：xxx」、`url` → 「链接：xxx」），白话档折叠组面板自动按规则渲染该工具行。
2. 想更精准时再补 `doing` / `done` / `arg`；想让它默认折叠则加 `complex: true`。
3. 白话档折叠组面板会把组内所有工具（含产品有原生卡片的 `read` / `write` 等）按规则渲染成白话行；原生档下它们仍是产品原版卡片，无需特殊处理。
